# Browser Comparison Report (research snapshot: 8 Nov 2026)

## Scope and cautions
The comparison below synthesizes vendor product documentation, project documentation and public reviews. Feature availability can vary by OS, release channel, account, geography and settings. Browser vendor performance claims are not comparable unless the same machine, OS, browser build, test pages, warm/cold state and measurement method are used. No memory/speed scores are asserted here: reliable same-build, same-M1 test data was not gathered for all twelve browsers. RAM comparisons are especially sensitive to process accounting, cache state, extensions and sleeping-tab behavior. User reviews are subjective; they are evidence of common UX themes, not controlled product tests.

| Browser | Engine / strengths | Trade-offs and UX | Privacy, security, AI, tabs |
|---|---|---|---|
| **Chrome** | Chromium/Blink + V8; broad site compatibility, largest extension ecosystem, frequent releases, strong developer tools. Clean familiar toolbar. | Google account/sync ecosystem; multi-process and extensions can use substantial memory; built-in UI customization is modest. | Safe Browsing, password manager, Memory Saver and Energy Saver. Gemini/AI features are changing by region and release. Tab groups and memory controls; no first-party native ad blocker. |
| **Microsoft Edge** | Chromium/Blink, strong compatibility, vertical tabs and Microsoft integrations. | Product surface can feel crowded; account/cloud integration is a dependency for some features. | SmartScreen and tracking prevention; Sleeping Tabs/Efficiency modes and Copilot features. Tab groups/workspaces and vertical layout. |
| **Safari** | WebKit/JavaScriptCore, OS-native, tight Apple hardware, Keychain and OS integration; generally a compelling battery-conscious Mac choice. | macOS-only desktop; Chrome extension catalog is not compatible (Safari Web Extensions are a separate format); engine/OS release coupling. | Intelligent Tracking Prevention, Privacy Report, profiles, Tab Groups, iCloud Keychain and Reader. Apple has added WKWebView/WebKit capabilities, but a WKWebView shell is not Safari. AI varies by macOS/Apple Intelligence availability. |
| **Firefox** | Gecko/SpiderMonkey, open source, independent engine, broad Firefox add-ons and strong customization. | Some sites optimize first for Chromium; interface density/preferences can challenge new users. | Enhanced Tracking Protection and Total Cookie Protection; Firefox has shipped vertical tabs and is adding opt-in AI controls. Container-style separation and tab groups; extensive privacy controls. |
| **Brave** | Chromium with Chrome Web Store compatibility; built-in Shields, fast Chromium compatibility. | Strong blocking can break sites; optional crypto/rewards surface is not for everyone. | Tracker/ad blocking and fingerprinting protections, private windows including Tor option in desktop product, Leo assistant. Standard and vertical tab options; built on Chromium, so Chromium/extension constraints apply. |
| **Opera** | Chromium; polished feature-rich interface and integrated services. | Larger product surface and service integrations; built-in VPN is a browser proxy feature, not a general device VPN. | Built-in ad/tracker blocker, VPN service, AI, workspaces, tab islands, split screen, sidebar apps. Privacy/AI service details should be reviewed per feature. |
| **Opera GX** | Opera/Chromium with gaming-oriented customization and GX Control. | Visual style and gamification may be distracting; resource limiters can throttle workloads rather than make pages inherently efficient. | CPU/RAM/network limiting controls, ad blocking, AI and integrations; useful for resource visibility, but controls are not a promise of low baseline memory use. |
| **Vivaldi** | Chromium; extensive UI customization, tab stacks, workspaces/tiling, notes and integrated productivity tools. | Many settings/features create a learning curve and a comparatively busy surface. | Built-in tracker/ad blocker, per-site controls, tab stacking/tiling/hibernation, mail/calendar/feeds; Chromium compatibility and extensions. |
| **Arc** | Chromium with a distinctive sidebar, Spaces, profiles and split views. | The vendor shifted focus away from new Arc feature development (announced May 2025); this is a support/long-term investment caveat for new adopters. | Strong workspace UX, extensions and selected AI features; maintenance/security-update policy should be checked on the official site. Vertical tabs, Spaces and auto-archiving distinguish it. |
| **Zen Browser** | Open-source Firefox/Gecko-based project with a modern compact UI. | Newer project; release stability, feature parity, and update cadence require users to monitor releases. | Vertical tabs, workspaces, split views and customizations; Firefox privacy/extension foundation, not Chrome Web Store compatibility. No broad mature first-party AI suite documented in this snapshot. |
| **DuckDuckGo Browser** | WebKit-based on Mac (platform implementation varies); simple privacy-focused product. | Fewer advanced power-user, extension and customization capabilities than mature desktop browsers. | Tracker protections, email protection, cookie-popup handling, Fire Button and optional Duck.ai offerings; clean/simple tab model. Vendor says its protections are designed to block trackers without collecting browsing profiles. |
| **Dia** | Chromium-based Mac browser from The Browser Company; AI-first context and work workflows. | Young product; AI-centered interactions and cloud/provider handling are key adoption/privacy considerations. Product/platform scope is narrower than multi-platform browsers. | AI can use explicitly supplied tab/page context; current product material describes local encrypted browser data and sending only request-relevant content to AI services. Tab groups, profiles, split/work contexts and skills are evolving. |

## Technology choice for this implementation
**Selected for the actual code here: Electron + bundled Chromium**, because it delivers a real embeddable Chromium engine and the best practical route to Chrome-compatible site rendering, Chromium DevTools, modern standards and an ARM64 macOS package from a small team. It is not equivalent to shipping Chrome: the UI/browser services are ours, and Chrome Web Store install/extension parity is not delivered by this starter.

| Option | Advantages | Costs/risks | Decision |
|---|---|---|---|
| CEF | Native C/C++ embedding, Chromium engine control, flexible embedding APIs and multi-process rendering. | Large complex macOS helper-bundle/signing integration; CEF release tracking and Chromium updates are our responsibility; Chrome browser UI/extension compatibility is not automatic; substantial native implementation work. | Strong eventual choice for a highly native product with a dedicated C++ team, but too risky for this first build. |
| Electron + Chromium | Bundled, modern Chromium; mature cross-platform packaging/ecosystem, hardware acceleration and webContents DevTools; ARM64 mac targets. | Large bundle and memory overhead; bundled engine must be promptly updated; Node/IPC attack surface; browser extension APIs and Chrome UI are not automatically included. | **Chosen** with strict process separation and explicit security/release obligations. |
| Native macOS + WKWebView | Small, native UI, OS-managed WebKit, Keychain, system integration and lower runtime duplication. | WebKit, not Blink/V8; Chrome Web Store extensions do not directly work; parity and engine version follow OS; custom browser capabilities and media support differ from Safari. | Excellent Mac-native lightweight browser alternative if Chrome extension compatibility is deprioritized; not selected for this stated requirement. |
| Gecko / Firefox embedding | Independent engine and privacy/extension ecosystem. | Gecko embedding is not a simple supported browser-shell distribution path; distribution, update and integration burden is high. | Not selected. |

## Gaps in the market / our differentiators to pursue
- Tab management frequently hides the cost of sleeping/reloading; expose measured per-tab memory, suspend state and an easy restore history without claiming false savings.
- Put privacy states, site permissions and tracker blocks in one comprehensible dashboard with per-site overrides.
- Make workspaces local-first and separate their histories/cookies only when the user explicitly opts in.
- Multi-tab research should cite exact source tabs and snippets; AI should send the minimum selected context and display exactly what leaves the device.
- Keep AI optional and provider-portable; no API key or cloud account needed for base browsing.
- Provide explainable resource management, session snapshots, notes attached locally to URLs, and an offline-friendly research export.
